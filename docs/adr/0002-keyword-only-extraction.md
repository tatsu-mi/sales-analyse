# ADR-0002: SESに限定し、引用生成を省いたキーワード抽出を行う

- 日付: 2026-10-23
- 状態: 採用
- 関連: [ADR-0001](0001-integrated-skill-matching.md) の抽出形式・原文検証の方針を変更する。

## 背景

初回分析で、市況メモ、受託案件、原文引用、複雑な必須条件式を生成していた。出力が重く、出力上限による分割や再試行につながる。利用者の判断により、原文との厳密な対応による精度を一部犠牲にし、キーワード中心の照合へ簡略化する。

## 決定

- 市況メモ `market_notes` を出力しない。
- 対象はSES要員募集のみ。受託開発はその他として扱い、案件抽出・ランキング・通知の対象から外す。混在メールではSES募集だけを抽出する。
- 既存の `priority_rules.md` に受託欄があっても無視する。新しいサンプルには受託欄を設けない。
- AIに根拠引用を生成させない。案件・共通条件判定・プロフィール・通勤情報の引用欄を廃止し、原文との部分文字列一致の検証も行わない。
- 必須スキルは `terms`（キーワード）、`operator`（all/any）、`experience`（実務指定等）、`min_months`（必要経験月数）の一覧で抽出する。複雑な入れ子の条件式はAIに生成させない。
- 必須条件の内部判定形式、歓迎・関連条件のIDと表示名はプログラムで生成する。歓迎・関連条件は `kind` と `terms` だけをAIから受け取る。
- 統合キーワード照合へは案件ID・要件ID・短いキーワード情報だけを渡す。元本文、引用、個人の詳細は渡さない。
- 個人別の必須条件チェック、非実務経験の0.1倍加点、重複加点の抑制、Top10作成は引き続きAIを使わない。開始時期等の共通条件は初回分析で判定し、通勤条件は保存された情報で比較する。
- キーワード化できない必須条件は短い確認事項として保持し、未確認の案件には要確認の判定を付ける。

## 個人別Top10の統合（2026-10-23追記）

利用者の指示により、適合確認済みと要確認の別枠を廃止し、個人ごとに合わせて上位10件までを選定する。適合確認済みを優先し、各状態の中では得点順、続いて募集中の明記・受信日時・UID・案件キーで並べる。同一メールの複数案件は、この順序で最上位となる案件で代表する。明確な不適合は引き続き除外する。

`ranked_emails.json` の各人の候補は `entries` に統合し、各案件の適合・要確認の判定は残す。レポートと通知も個人ごとに一つの一覧とする。全候補の判定履歴は `engineer_assessments.json` に保持する。ADR-0001の要確認を別枠とする方針は本変更で置き換える。

## 原文の表示

レポートの参照元メール全文は残す。保存済み `emails.jsonl` から選定されたUIDのメールを取り出して転載するだけで、AIによる生成・照合を行わない。この転載はAIトークンを消費しない。中間の抽出・集約データへ元本文を重複保存する必要もない。

## 影響と検証

原文引用や詳細な論理構造による誤抽出検出は行わない。複雑な条件の意味を完全に再現することより、出力量の削減を優先する。実データでの精度・トークン削減量は別途確認する。

パイプライン版を7、統合マッチング版を3へ更新する。プロフィール抽出も変更したため、引用付きの旧キャッシュは流用しない。旧版からのresume移行は実装せず、新規実行を前提とする。

オフラインテストでは、引用なしのキーワード抽出、単純なAND/OR、実務区分・必要月数、受託の除外、個人別ランキング、原文の機械的な転載を確認する。
